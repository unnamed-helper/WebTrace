# Security Policy

## Scope

This project is a local defensive log-analysis tool. Security reports should focus on vulnerabilities in the application itself, unsafe processing of untrusted log input, data exposure, or other issues that could affect analysts using the tool.

## Do not publish sensitive evidence

Do not include real customer logs, credentials, tokens, personal information, internal hostnames, or confidential incident data in a public GitHub issue.

For a private vulnerability report, use the repository's GitHub security reporting mechanism when enabled by the repository owner.

## Detection limitations

A detection is not automatically proof of compromise. Analysts should validate suspicious events against authoritative application, identity, endpoint, WAF, and network telemetry.
